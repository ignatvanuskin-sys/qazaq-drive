## 1. Что изменено в этой итерации

### 1.1 Первый экран: фото как полноэкранный фон (главный запрос)

Было: справа отдельная карточка-фото, на мобиле — блок под текстом, кадр обрезался на ~47 %.
Стало: фото — фоновый слой на весь первый экран, текст поверх него.

- `src/app/[locale]/page.tsx`: `<Image fill priority sizes="100vw">` + два скрима (линейный 0.78→0.34→0.72→0.97 и радиальный), контент прижат к низу.
- Высота героя: `min-h-[100svh]` на мобиле, `92svh` от `sm` — фото закрывает экран целиком, включая область под прозрачной шапкой (hero поднят на `-mt-[68px]` / `sm:-mt-[76px]`).
- Фокус кадра смещён (`object-[62%_center]` на мобиле), чтобы автомобиль и дорога оставались в кадре при вертикальной обрезке.
- Полоса статистики вынесена из героя в отдельный блок на `--color-ink-2`, чтобы цифры не конкурировали с фото.
- Цвета `eyebrow` и `lead` в герое переопределены с `!` — иначе `--color-muted` из компонентного CSS перебивал их (текст был тусклее задуманного).

## 2. VERIFIED — что реально проверено

### Мобильный (320×568, 390×844, 430×932)

- **Герой:** секция = 844 px при viewport 844 px, фото 380×844 `object-fit: cover`, край в край, без разрывов.
- **Читаемость:** H1 `rgb(244,243,241)`, лид `rgba(244,243,241,0.82)`, eyebrow `0.72` — контраст достаточный на тёмном кадре.
- **Фиксированные элементы при `scrollY=0`:** ни бара, ни AI-кнопки (0 видимых `position: fixed`).
- **При `scrollY=1200`:** FAB 56×50 @ 707–757, бар 380×69 @ 775–844 → зазор 17.8 px, взаимного перекрытия нет.
- **Горизонтальный скролл:** `scrollWidth == clientWidth` на `/ru` и `/ru/booking` (вертикальный скроллбар учтён).
- **`/ru/booking`:** карточка формы первая (top 117 → 767), интро ниже (799); «Далее» `position: static` внутри карточки, не перекрывает варианты шага.
- **Валидация:** пустой шаг 1 → «Выберите, что вас интересует»; пустой шаг 3 → 3 ошибки, `aria-invalid` на name/phone/consent, фокус переходит на `input[name=name]`.
- **Маска телефона:** `87001234567` → `+7 700 123 45 67`, `type=tel`, `inputmode=tel`, `autocomplete=tel`.
- **Черновик формы:** `sessionStorage.qds_booking_draft`, восстановление шага и данных; смена языка данные не теряет.

### Функциональность

- **Модалка:** 4 шага, 4 варианта интереса, селект категории, форматы, окна времени, honeypot вне экрана, consent. Esc закрывает, `body` разблокируется.
- **Заявка:** создаётся только после ответа сервера; дедупликация по телефону+интересу за 15 минут; невалидные данные → 422 с полями; honeypot и «слишком быстро» → отказ.
- **Админка:** вход через форму, дашборд с «Всего заявок», список заявок, карточка лида, CSV с кириллицей.
- **Лайтбокс галереи:** `role=dialog`, `aria-modal`, счётчик 1/5 → 2/5, Next/Esc/Close, блокировка скролла.
- **Меню:** 40×40, `aria-expanded` меняется, панель непрозрачная, ссылки 58 px по высоте, скролл блокируется.
- **Ссылки:** `tel:+77080861028` = отображаемому номеру; `wa.me/77080861028` ведёт на профиль QazaqDriveSchool; 2GIS → карточка фирмы (не поиск).
- **FAQ:** нативные `<details>`, работают без JS, мульти-раскрытие, overflow не появляется.

### Техническое

- `npm run build` — успешно, TypeScript strict без ошибок.
- Console errors на `/ru`, `/ru/booking`, в модалке: **0**.
- 4xx/5xx: **нет**; все чанки, шрифты, CSS, `_next/image` — 200.
- `/kz` отдаёт полный казахский контент, переключение сохраняет маршрут.
- SSR-разметка содержит Schema.org `DrivingSchool`, canonical, `hreflang` ru/kk, OG-теги, sitemap и robots.

## 3. Открытые вопросы (не блокеры)

### P3

1. **AI-кнопка может задевать правый край кнопок в контенте** (~29 px на узком экране при определённой прокрутке). Кнопка непрозрачная, z-30; тап по 90 % площади работает. Лечится уменьшением FAB до 44 px или скрытием при скролле вверх.
2. **`POST /api/track` → 204 + `net::ERR_ABORTED`** — beacon обрывается при навигации. Не ошибка сервера, но часть page-view может не долетать; для точной аналитики стоит отправлять через `navigator.sendBeacon`.
3. **Третья ошибка валидации (согласие) ниже среза** на 390 при пустом шаге 3: 2 из 3 сообщений видны без прокрутки. Решение — компактный error-summary вверху шага.
4. **Расхождение цифр соцдоказательства:** герой «144 оценки», блок «129 отзывов», живая карточка 2GIS — 132 отзыва. Подписи разные («оценки» ≠ «отзывы»), но рядом выглядят противоречиво; данные в `brand.rating` стоит переснять перед запуском.
5. **Тап-таргеты 36–40 px** у крестика модалки и стрелок лайтбокса (норма 44).

### P2 (продуктовое, требует решения владельца)

6. **Цена, сроки и документы — «Уточняется»** в 3 из 5 вопросов FAQ и в карточках программ. Это следствие требования не выдумывать данные: школа не публикует прайс. Конверсия вырастет, только когда владелец внесёт значения в админке.
