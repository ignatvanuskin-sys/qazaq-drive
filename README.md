# QAZAQ DRIVE SCHOOL — премиальная платформа автошколы

Сайт-платформа для автошколы в Алматы: витрина бренда, многошаговая запись,
AI-консультант, автоматизация заявок (Telegram / CRM / email), закрытая
админ-панель и аналитика источников. RU/KZ, mobile-first.

> Всё, что касается фактов о школе (адрес, телефон, категории, рейтинг),
> взято из публичной карточки 2GIS и заголовка Instagram. Данные, которых
> школа не публикует (цены, сроки, автопарк, инструкторы), **не выдуманы** —
> они показываются как «уточняется» / «по запросу» и заполняются в админке.

---

## 1. Стек

| Слой | Выбор |
|---|---|
| Framework | Next.js 15 (App Router, RSC), TypeScript strict |
| UI | React 19, Tailwind CSS v4, собственные компоненты, CSS-анимации |
| Данные | Prisma ORM; SQLite локально, PostgreSQL в продакшене |
| Auth | Сессия в httpOnly cookie, HMAC-SHA256, scrypt-пароли |
| AI | Серверный адаптер к любому OpenAI-совместимому API |
| Интеграции | Telegram Bot API, CRM webhook (HMAC), SMTP (nodemailer) |
| Аналитика | Собственные page-view события + источник/UTM; опционально GA4 |

Framer Motion не используется: анимации на CSS + `IntersectionObserver`,
чтобы не платить лишним JS за первый экран.

## 2. Быстрый старт

```bash
npm install
cp .env.example .env          # Windows: copy .env.example .env
# отредактируйте .env: AUTH_SECRET, ADMIN_EMAIL, ADMIN_PASSWORD

npx prisma generate
npx prisma db push            # создаёт prisma/dev.db
npm run db:seed               # админ + программы + FAQ

npm run dev                   # http://localhost:3000
```

`ADMIN_PASSWORD` короче 12 символов — сид не создаст администратора и
напечатает предупреждение. Это сделано намеренно.

Продакшн:

```bash
npm run build
npm start
```

## 4. Переменные окружения

Полный список — в `.env.example`. Ключевое:

| Переменная | Назначение |
|---|---|
| `DATABASE_URL` | SQLite или PostgreSQL |
| `AUTH_SECRET` | ≥32 символа, подпись сессионной cookie |
| `HASH_SALT` | соль для хеширования IP в логах |
| `ADMIN_EMAIL` / `ADMIN_PASSWORD` | первый администратор (только для сида) |
| `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID` | уведомления о заявках |
| `TELEGRAM_WEBHOOK_SECRET` | проверка подлинности webhook |
| `CRM_WEBHOOK_URL` / `CRM_WEBHOOK_SECRET` | выгрузка лидов в любую CRM |
| `SMTP_*`, `ADMIN_EMAIL_RECIPIENT` | письмо администратору |
| `AI_API_KEY` / `AI_BASE_URL` / `AI_MODEL` | AI-консультант |
| `AI_DAILY_MESSAGE_LIMIT` | жёсткий суточный лимит ответов (защита бюджета) |
| `NEXT_PUBLIC_SITE_URL` | канонический домен для SEO/OG |

Секреты читаются только на сервере. В клиентский бандл попадают только
`NEXT_PUBLIC_*`.

## 5. Интеграции

### Telegram
1. `@BotFather` → создать бота → токен в `TELEGRAM_BOT_TOKEN`.
2. Добавить бота в группу администраторов, написать сообщение, взять
   `chat.id` из `https://api.telegram.org/bot<TOKEN>/getUpdates`.
3. `TELEGRAM_CHAT_ID` — id группы (для супергрупп начинается с `-100`).
4. Webhook (нужен для кнопок «В работе» / «Обработана»):

```bash
curl "https://api.telegram.org/bot$TELEGRAM_BOT_TOKEN/setWebhook" \
  -d "url=$NEXT_PUBLIC_SITE_URL/api/telegram/webhook" \
  -d "secret_token=$TELEGRAM_WEBHOOK_SECRET"
```

Уведомление содержит ID заявки, имя, телефон, интерес, категорию, источник,
комментарий и время. Кнопки: «Связаться» (WhatsApp), «Позвонить»,
«В работе», «Обработана». Callback проверяется по secret-token, статус
пишется в БД и в историю заявки.

### WhatsApp
Кнопки ведут на `wa.me` с предзаполненным текстом. Это **не** автоматическая
отправка сообщений — для неё нужна WhatsApp Business Platform и согласие
пользователя. Архитектура к этому готова (сервисный слой `integrations.ts`),
но интеграция не имитируется.

### CRM
`POST` на `CRM_WEBHOOK_URL` с HMAC-подписью `x-qds-signature`, идемпотентным
ключом `x-idempotency-key` (= `publicId`) и 3 попытками. Ошибка пишется в
`Lead.crmError` и `IntegrationLog`. Провайдер не зашит — подойдёт любой
endpoint (Bitrix24, amoCRM, HubSpot, Make/n8n).

### Email
SMTP-письмо администратору. Клиенту письмо не отправляется: форма намеренно
не собирает email (минимизация данных). Если нужно — добавьте поле и шаблон
в `sendEmailNotifications`.

### AI-консультант
`POST {AI_BASE_URL}/chat/completions` с ключом из серверного env. База знаний
строится из тех же проверенных данных, что и сайт (`lib/knowledge.ts`):
категории, оплата, адрес, рейтинг, FAQ из БД. Модель обязана:
- отвечать только на языке интерфейса;
- не выдумывать цены/сроки/гарантии;
- при нехватке данных передавать вопрос администратору;
- собрать имя + телефон и вернуть служебный маркер `[[LEAD_READY:{...}]]`,
  по которому сервер создаёт заявку в общей базе (источник `chat`).

Защита: 20 запросов / 10 мин на IP, 40 / час на сессию, суточный лимит
ответов, таймаут 22 с. Если ключа нет — `/api/chat` отвечает 503 и виджет
честно показывает «AI временно недоступен» + кнопку обычной заявки.

## 6. Заявки и надёжность

Поток: валидация (zod) → дедупликация (телефон + интерес за 15 минут) →
запись в БД + событие `created` → рассылка в Telegram/CRM/email →
`notifiedAt` / `notifyError`.

- Успех показывается **только** после подтверждения записи в БД.
- Если Telegram/CRM/AI недоступны, заявка уже сохранена; ошибка видна в
  админке, есть кнопка «Отправить повторно».
- Антиспам: honeypot-поле, минимальное время заполнения, лимит по IP+UA,
  дедупликация, серверная валидация, согласие на обработку данных.
- Публичный номер заявки: `QDS-XXXXXXX` (без последовательных ID).

## 7. Админ-панель

`/{locale}/admin` — только после входа. Сессия 8 часов, httpOnly, SameSite=Lax,
Secure в продакшене; пароли — scrypt; вход ограничен 8 попытками / 10 минут.

- **Обзор** — заявки за сегодня/7 дней, конверсия (заявки/визиты), источники,
  статусы, последние обращения, список фактов, которые нужно заполнить.
- **Заявки** — фильтры (статус, источник, программа, даты), поиск по имени/
  телефону/ID, пагинация, экспорт CSV с учётом фильтров.
- **Карточка заявки** — все поля, UTM, consent, статус, внутренний комментарий,
  фиксация контакта, история событий, статус уведомлений, повторная отправка.
- **Контент** — программы (цены, сроки, состав), FAQ, инструкторы, автомобили.
- **Интеграции** — что настроено, какие переменные нужны, тест Telegram,
  журнал ошибок.
- **Настройки** — телефон/WhatsApp/email/адрес/график (сразу на сайте),
  смена своего пароля, создание администратора.

## 8. Двуязычность

`/ru` и `/kz` — отдельные URL, `hreflang` + canonical в метаданных.
Словари: `src/content/i18n/ru.ts` (эталон типов) и `kz.ts` (проверяется
компилятором на полноту). Выбор языка запоминается в cookie и не сбрасывает
черновик формы (sessionStorage). Формы, ошибки, чат, FAQ, админ-навигация —
на обоих языках.

## 9. SEO и производительность

- Уникальные `title`/`description` на каждую страницу и язык.
- Schema.org: `DrivingSchool` + `WebSite` + `BreadcrumbList` + `FAQPage`.
  **Без** `aggregateRating` — рейтинг 2GIS показывается на странице со
  ссылкой на источник, но не выдаётся за собственные структурированные данные.
- `sitemap.xml` с alternates, `robots.txt` (закрыт `/api` и `/*/admin`).
- OG-картинка `/og/cover.jpg`, метаданные для мессенджеров.
- `next/image` (AVIF/WebP), `priority` только на первом экране, `loading="lazy"`
  ниже, размеры заданы (нет CLS).
- Шрифты через `next/font` (self-hosted, без layout shift).
- Карта грузится по клику — сторонние скрипты не тянутся при первом рендере.
- `prefers-reduced-motion` отключает анимации.

Цели Core Web Vitals (LCP ≤2,5 с, INP ≤200 мс, CLS ≤0,1) **не заявлены как
достигнутые**: для подтверждения нужен замер Lighthouse на реальном домене
после деплоя (см. §12).

## 10. Безопасность

- Все формы валидируются на сервере (zod) — клиентская проверка только UX.
- SQL-инъекции исключены Prisma; XSS — React-экранированием, `dangerouslySetInnerHTML`
  используется только для собственного JSON-LD.
- Rate limiting в БД (переживает рестарты) + burst-защита.
- Webhook Telegram проверяется по `X-Telegram-Bot-Api-Secret-Token`.
- Security-заголовки в `next.config.ts` (nosniff, frame-options, referrer-policy,
  permissions-policy, HSTS).
- Персональные данные: только имя, телефон, комментарий; IP хранится хешем.
- Политика конфиденциальности — `/{locale}/privacy`.
- Секреты не попадают в git (`.gitignore`) и в клиентский бандл.

> Соответствие Закону РК «О персональных данных» должно быть подтверждено
> юридической проверкой владельца: сайт даёт технические механизмы (согласие,
> минимизация, удаление по запросу), но не является юридическим заключением.

## 11. Проверка перед запуском

```bash
npm run typecheck
npm run build
```

Ручной чек-лист:

1. `/` → редирект на `/ru` (или `/kz` при `Accept-Language: kk`).
2. Пройти запись на 4 шага → заявка появилась в `/ru/admin/leads` с ID.
3. Повторить ту же заявку → «похоже, уже отправлено» (дедупликация).
4. Отправить с неверным телефоном / без согласия → ошибки полей.
5. Войти в админку, сменить статус → событие в истории.
6. Экспорт CSV → открывается в Excel с кириллицей.
7. Telegram: заявка пришла, кнопки меняют статус (если настроен webhook).
8. AI: вопрос о цене → честный ответ «уточнит администратор»; при отсутствии
   ключа — виджет предлагает форму.
9. Переключить RU→KZ на середине формы → данные сохранены.
10. Проверить 320 / 375 / 390 / 430 / 768 / 1024 / 1440 px, без горизонтальной
    прокрутки, фокус с клавиатуры виден.

## 12. Деплой

### Vercel
1. Подключить репозиторий.
2. `DATABASE_URL` — PostgreSQL (Neon/Supabase/RDS). В `prisma/schema.prisma`
   заменить `provider = "sqlite"` на `"postgresql"`.
3. `npm run build` уже включает `prisma generate`; миграции — `prisma migrate deploy`.
4. Добавить переменные окружения из `.env.example`.
5. `NEXT_PUBLIC_SITE_URL` = боевой домен (иначе canonical/OG будут неверными).

### VPS / Docker
```bash
npm ci
npx prisma migrate deploy
npm run build
npm start            # PM2 / systemd, reverse-proxy nginx + HTTPS
```

SQLite подходит для одного инстанса и небольшого трафика; при нескольких
инстансах нужен PostgreSQL.

## 13. Что требует действий владельца

| Что | Где |
|---|---|
| Цены, сроки, состав программ | Админка → Контент → Программы |
| Инструкторы (ФИО, фото, языки) | Админка → Контент → Инструкторы |
| Автопарк (марки, модели, фото) | Админка → Контент → Автомобили |
| График работы (время закрытия) | Админка → Настройки |
| Перечень документов, лицензия | Админка → Контент → FAQ |
| Telegram-бот и webhook | Env + `setWebhook` |
| CRM / SMTP / AI-ключи | Env |
| Реальные фото вместо демонстрационных | `public/images/*` + админка |
| Юридическая проверка политики ПДн | До публикации |

Демонстрационные фотографии (`public/images/hero.jpg`, `practice.jpg`,
`theory.jpg`, `fleet.jpg`, `interior.jpg`, `city.jpg`) — сгенерированные
изображения атмосферы, **не** фото автопарка школы; подписи на сайте это
указывают. Замените их реальными кадрами.

## 14. Источники данных о школе

- 2GIS — карточка организации (адрес, телефон, email, категории A–D1E,
  способы оплаты, рейтинг 5,0 / 144 оценки / 129 отзывов, открытие в 09:00,
  3 филиала), проверено 2026-10-21.
- 2GIS — отзывы (тексты и имена авторов перенесены без правок).
- Instagram — публичный заголовок профиля (описание, 4 421 подписчик, WhatsApp).
  Лента и Reels недоступны без авторизации, поэтому визуальный стиль постов
  не изучался; акцентный цвет задан как токен `--color-accent` и меняется
  в одном месте.
